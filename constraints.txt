# Pinned transitive dependency versions for every automated install.
#
# Why: pyproject.toml pins only yfinance (statement row labels drift) and floors
# the rest, so a transitive release could break the 10:00 UTC run and we would
# only learn about it from the failure alert. This file freezes the whole
# resolved set, so the scheduled workflows and CI install the same versions
# every day and a dependency upgrade becomes a reviewable diff.
#
# Used as: pip install -e . -c constraints.txt
# (CI: pip install -e ".[dev]" -c constraints.txt)
# A constraints file never installs anything on its own: it only pins a version
# for packages the install already pulls in. Dev-only tooling (pytest and its
# dependencies) is therefore listed here too and stays uninstalled in the
# runtime workflows.
#
# Refresh procedure:
#   1. python3 -m venv .venv && .venv/bin/pip install -e ".[dev]"   (fresh venv,
#      no -c, so pip resolves the newest set pyproject.toml allows)
#   2. .venv/bin/pip freeze --exclude-editable > constraints.txt
#   3. restore this comment block at the top, run scripts/checks.sh, and commit
# A deliberate dependency upgrade (editing pyproject.toml) means regenerating
# this file in the SAME pull request, or the pin silently overrides the bump.
#
